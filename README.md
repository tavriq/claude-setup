# claude-setup — как я веду разработку через агентов Claude Code

Окружение и порядок работы, на которых я веду разработку через агентов: код пишут сессии Claude Code, «готово» решает проверка, правила держат хуки и скрипты.

## Как устроено

```
 глобальные правила    ~/.claude/CLAUDE.md, rules/sessions-protocol.md
        |              как спорить, как планировать, как переписываться
        v
 правила проекта       <репо>/CLAUDE.md, .claude/rules/ (грузятся по путям файлов),
        |              .claude/bash-guard.json (свои запреты репо)
        v
 сессии-роли           техлид  --задание файлом-->  разработчик 1..4   (шаблоны в roles/)
        |              у каждой сессии свой git worktree; связь сообщениями по адресу
        |              из cc-who; перед /clear и /compact сессия пишет handoff
        v
 гейты                 bash-guard (block / confirm по цитате / ask), хуки проекта,
        |              линтер хуков на старте, тесты, ИИ-ревью перед релизом
        v
 человек               план, согласование, «го» на опасное и на прод
```

## Цикл задачи

1. **Триаж.** Сессия оценивает задачу как мелкую, среднюю или крупную. Мелкую и среднюю делает сама, на крупную задаёт вопросы и пишет план.
2. **План и согласование.** Крупная задача идёт через Plan Mode, код начинается только после моего «да».
3. **Код в worktree.** Техлид пишет задание файлом по шаблону `roles/task-brief.md`: что и зачем, контракт, сценарии приёмки, формат сдачи. Разработчик работает в своём worktree и не трогает соседние деревья.
4. **Тесты.** Сначала целевые по затронутому, потом полный прогон у техлида. Принятый тест — часть приёмки: агент меняет его только с причиной, которую я вижу в отчёте.
5. **PR и ИИ-ревью.** Ревьюер-субагент (`agents/code-reviewer.md`) получает только diff, без контекста задачи, и ничего не правит.
6. **Приёмка.** Техлид сверяет отчёт разработчика, diff и прогон, потом сносит worktree.
7. **Выкат по «го».** Прод выкатывается только по моему согласию в окне той сессии, которая выкатывает. Просьба соседней сессии согласием не считается.

## Что внутри

Каждый компонент появился после ошибки, которая повторилась. Если правило можно проверить кодом, я пишу хук или скрипт. Строку в CLAUDE.md агент пропускает, хук он обойти не может.

| Компонент | Что делает | Какую ошибку закрыл |
|---|---|---|
| `hooks/bash-guard.py` | Хук перед каждой shell-командой. Разбирает её своим лексером вместе с кавычками, heredoc, `bash -c`, `$(…)`, `ssh хост '…'`, `docker exec` и даёт один из трёх ответов. `block` отказывает без исключений. `confirm` отказывает, пока в команде нет `#danger-ok: <дословная цитата моего согласия>`. `ask` открывает окно мне. Каждое срабатывание пишется в лог, секреты в нём маскируются | `rm -rf` по корню и репо, force-push, запись поверх `.env`, `pm2 restart all` на сервере, смена защиты веток, стёртый ключ ssh-хоста |
| `bash-guard.example.json` | Прод-хосты, защищённые ветки, свои правила-регулярки. Проектный `.claude/bash-guard.json` добавляет запреты репо | разные запреты в разных репо |
| `bin/cc-who` | Адресная книга сессий: по имени роли из `/rename` отдаёт текущий адрес для сообщения. Хук на старте говорит сессии, кто она | после перезапуска редактора адреса меняются, а имя роли остаётся только в истории сессии |
| `rules/sessions-protocol.md` | Переписка сессий: не больше трёх раундов, одно сообщение на событие из четырёх блоков, на «ок» не отвечать | сообщение прерывает адресата посреди работы и тратит его контекст |
| `roles/` | Промпт техлида, шаблон задания разработчику с форматом отчёта, промпт «после клира», по которому сессия продолжает с того же места | задача и правила жили только в контексте сессии и пропадали после `/clear` |
| `skills/handoff` | Хвост перед `/clear` и `/compact`: что сработало и чем это доказано, что нет, что не пробовали, следующий шаг | после очистки контекста терялись детали: что проверено, а что только предположено |
| `hooks/context-warn.sh` | Предупреждает, когда контекст последнего хода перевалил порог | старая оценка «размер файла / 4» завышала в разы |
| `bin/check-hooks-config` | На старте сессии проверяет, что matcher каждого хука вообще может сработать, а скрипт на месте и исполняемый | matcher `Bash(git push:*)` сравнивается с именем тула, а не с командой. Такой хук не срабатывает ни разу, и снаружи этого не видно |
| `CLAUDE.md` | Протокол мнения (сначала контраргумент), триаж задач, план, дело и проверка | модель соглашается с любой идеей |
| `skills/council` | Совет независимых субагентов: вопрос без моей позиции, анонимная взаимная критика, свод | ответ подстраивается под позицию автора вопроса |
| `tests/` | Таблица опасных и безопасных команд для стража, тесты `cc-who` и линтера на поддельных конфигах, проверка, что в репо нет локальных путей | при переносе на Linux таблица поймала дыру: `rm -r` внутри любого каталога с именем tmp проходил молча |

Ещё в репо субагенты для ревью и поиска (`agents/`) и три вспомогательных скилла. `commit` коммитит и пушит только свою ветку задачи, `worktree` заводит дерево под задачу вместо нового клона, `stop-slop` вычищает из текста обороты ИИ.

## Что работает плохо

- **Узкое место в ревью.** PR вливается за минуты, и я вижу итог, каждую строку не читаю. Ошибку, которую пропустили тесты, полный прогон и ИИ-ревью, пропущу и я.
- **Страж видит только текст команды.** Скрипт, который сам делает force-push внутри, он не остановит. Цитату в маркере агент тоже может выдумать, поэтому confirm — тормоз и след в логе, а не замок. Замок — block и ask.

## Быстрый старт

```bash
git clone https://github.com/tavriq/claude-setup.git
cd claude-setup
./install.sh                  # прогонит тесты, спросит, как к тебе обращаться
./install.sh --dry-run        # показать, что будет сделано, ничего не трогая
```

Установщик сначала прогоняет тесты: со сломанным стражем он не ставит ничего. Всё, что перезаписывается, уходит в `~/.claude/backups/setup-<время>/`. Свои `settings.json` и `bash-guard.json` он не трогает, новый `settings.json` кладёт рядом.

Роли: в окне сессии `/rename техлид`, первым сообщением — «Прочитай ~/.claude/roles/tech-lead.md и работай по нему». Разработчикам так же, с заданием из `roles/task-brief.md`.

Проверка после установки: в новой сессии команда `echo bash-guard-ask-probe` должна открыть окно подтверждения, `~/.claude/bin/cc-who` — показать таблицу сессий. Тесты отдельно: `python3 -m unittest discover -s tests`.

Выключить страж на время: `touch ~/.claude/bash-guard.off`, включить обратно — удалить файл.

## Чего здесь нет

- MCP-серверов и плагинов, они ставятся отдельно.
- Секретов: токенов, паролей, внутренних хостов. Найдёшь — это баг.
