# Commit

Автоматический коммит и push в формате **conventional commits**.

## Когда вызывать

- Добавил новую функциональность → `feat`
- Исправил баг → `fix`
- Обновил документацию → `docs`
- Рефакторинг без изменения поведения → `refactor`
- Тесты → `test`
- Конфиги, сборка, инструменты → `chore`
- В конце рабочей сессии (если были изменения)

**Без вопросов.** Не спрашивай «сделать коммит?», «запустить?», «какое сообщение?» — просто делай.

---

## Workflow

### Шаг 1: Проверить статус

```bash
git status
```

Если нет изменений → ничего не делать, выйти.

### Шаг 2: Определить scope

Посмотри какие папки затронуты (`git diff --name-only`):

| Изменения в | scope |
|---|---|
| `mobile/` | `mobile` |
| `backend/` | `backend` |
| `docs/`, README, *.md | без scope, тип = `docs` |
| `.github/`, CI | без scope, тип = `chore` или `ci` |
| `shared/` | `shared` |
| смешанное | без scope |


### Шаг 3: Добавить файлы

```bash
git add <конкретные файлы>
```

**ВАЖНО:**
- НЕ используй `git add .` или `git add -A`
- Добавляй только конкретные изменённые файлы по именам

**Что НЕ коммитить:**
- `.env`, секреты, токены, ключи, `*.keystore`
- `tmp/`, `node_modules/`, `.venv/`, `venv/`
- `__pycache__/`, `*.pyc`, `.DS_Store`
- `*.log`

### Шаг 4: Коммит

```bash
git commit -m "<type>(<scope>): <описание>"
```

**Формат:**
- На **русском** языке
- Тип на английском: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `style`, `perf`
- Scope в скобках (опционально, если узнаваемо): `(mobile)`, `(backend)`, `(shared)`
- Описание короткое (1 строка, до 70 символов)
- Без точки в конце

**Примеры:**
- `feat(mobile): добавлен экран ShiftDetail с фото-прибытием`
- `fix(backend): исправлена валидация координат в /arrive`
- `docs: обновлён ONBOARDING под Phase 3.1`
- `chore(mobile): обновлены peer-deps под RN 0.74`
- `test(mobile): покрыт useAuth keychain-моком`
- `refactor(backend): вынесена логика shift-reminders в lib/`

### Шаг 5: Push

```bash
git push
```

- Если remote не настроен → сообщи пользователю, не падай
- Если push не прошёл (нет прав, конфликт) → сообщи и предложи решение
- **Никогда** не делай `git push --force` без явной просьбы {{USER_NAME}}
- **Никогда** не пушь напрямую в `main`/`master` — только через PR

### Шаг 6: Бэкап .env (опционально)

Если в проекте есть `.env` и настроен бэкап-путь:

```bash
PROJECT_NAME=$(basename "$PWD")
BACKUP_DIR="$HOME/Library/Mobile Documents/com~apple~CloudDocs/.env-backups/$PROJECT_NAME"
mkdir -p "$BACKUP_DIR"
cp .env "$BACKUP_DIR/.env"
```

- Если `.env` нет → пропусти этот шаг
- Путь бэкапа подстрой под пользователя (iCloud, Dropbox, локальная папка)

## Правила

- Работай в **текущей ветке** — не создавай новые без просьбы
- Для изолированной работы → используй `worktree` skill
- Если ты в проекте с `feat/<name>` веткой и есть незакоммиченные изменения смешанные с чужими → НЕ коммить, сначала уточни у пользователя
- Если pre-commit hook упал → НЕ amend, NEW commit после фикса (см. правила Bash в Claude Code)

## Checklist

- [ ] `git status` → есть изменения
- [ ] Тип и scope определены по содержимому диффа
- [ ] `git add` конкретных файлов (не `.env`, не `tmp/`)
- [ ] `git commit` в conventional формате на русском
- [ ] `git push` (если remote настроен)
- [ ] Бэкап `.env` (если есть и настроен путь)
- [ ] Рапорт: «Проверил: коммит ✓, push ✓, файлы корректны ✓»
