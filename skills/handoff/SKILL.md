# Handoff

Файл для следующей сессии (или для себя после /clear и /compact). Справка, а не приказ: перед действием по нему — сверить с git и кодом.

## Куда

```bash
~/.claude/bin/cc-who --me                                # «ты — <имя>, адрес …»
git rev-parse --path-format=absolute --git-common-dir    # проект = каталог над .git (worktree → главное репо)
```

Путь: `~/.claude/handoff/<проект>/<имя>-<YYYY-MM-DD-HHMM>.md`, пробелы в имени → `-`; вне git проект = имя cwd.
Время — из `date`, не на глаз. Каждый раз новый файл, старые не трогать. Живут 7 дней: старше удаляет хук SessionStart
из `settings.json`. В конце — путь одной строкой человеку.

## Что внутри (до 60 строк)

```markdown
# <имя> · <проект> · <дата время>
Задача: <одна строка> · cwd: <путь> · ветка/worktree: <…> · PR: <№ или нет>

## Сработало
- <что> — доказательство: <команда и её вывод одной строкой / PR / коммит / путь к файлу>

## Не сработало
- <что пробовал> — <почему не вышло: ошибка, факт, на чём упало>

## Не пробовали
- <идея/вариант> — <почему отложено>

## Следующий шаг
<одно точное действие: файл, команда, кому написать; что ждёт согласия человека>
```

## «Могу клирить / компакт?»

Перед ответом проверь: `git status --short` и непушнутые коммиты (`git log @{u}..`) в своём дереве; свои фоновые задачи
и агенты ещё идут; обещанное и не сделанное (сообщение сессии, отчёт, PR без сдачи). Потом запиши хвост и ответь одной строкой:
«да — хвост: <путь>» или «нет: <что висит>; сначала <действие>». Для /compact хвост тоже пишется — компакт теряет детали.

## Правила

- «Работает» без доказательства — пиши «не проверено», а не «сработало».
- Секреты, пароли, токены, номера карт, телефоны — не писать (только имена ключей и пути).
- Факты — из этой сессии; чего не знаешь — так и пиши, не додумывай.
- Читать хвост при старте — только когда человек попросит или задача прямо продолжает прошлую.
